## 1. 目标与状态

目标：为后续前端提供页面入口、操作结果、空态、加载及失败反馈的产品标注。本轮仅写已确认的交互，不编写页面代码、不选技术、不提供聊天增长优化方案。

本轮实际完成：与发起人确认启动加载与转场、启动失败、首页两个模块空态，以及新增填写面板的成功失败行为；v0.2 补充关闭未保存内容确认、删除结果、列表／表单通则和聊天顶部输入状态。其余页面沿用先前确认，并明确未补齐处；不将本文件视为所有前端状态已经验收。

依据：2026-10-30 本聊天中发起人的直接选择与确认。只公开产品结论，不含真实用户资料、上传素材、私人聊天或本地参考媒体路径。需求确认不是功能或动效测试。

## 2. 启动加载与页面入口（已确认）

| 标注 | 用户可见行为 |
| --- | --- |
| 打开 LUNE | 全屏使用当前日／夜模式的渐变，居中仅呈现品牌，不显示情头 |
| 品牌文字 | LUNE；固定中文主题句“爱与故事，永不落幕。”，不新增或改写品牌文案 |
| 加载指示 | 不显示虚假进度，不为展示而刻意延长等待；轻微呼吸效果仅为此前建议，尚未单独确认 |
| 加载成功 | 品牌上浮至目标页面的正确品牌位置，目标页面内容同步显现，形成连续过渡 |
| 未登录 | 以相同过渡显现手机号登录／注册页 |
| 已登录、首次资料未完成 | 以相同过渡显现首次关系引导页 |
| 已登录、资料已完成 | 以相同过渡显现首页 |
| 启动失败 | 保留品牌及渐变，显示“这次没能顺利打开，再试一下吧。”，下方仅显示重试箭头；不因失败自动跳转或清空资料 |
| 重试 | 箭头重试启动加载，成功后再按账户状态进入对应页面，不把加载失败当作未登录或没有资料 |

转场细则：首页、登录、首次引导都沿用品牌上浮与页面内容同步显现。具体速度、曲线、首页品牌落点和减少动态效果的适配尚待制作及后续评审；本文件不擅自写成已确认数值，不制作动画代码。

## 3. 首页纪念日与备忘录（本轮确认）

| 模块／操作 | 入口与结果 | 空态 | 加载与失败 |
| --- | --- | --- | --- |
| 纪念日 | 首页纪念日模块提供添加入口；点击从底部展开填写面板 | “把值得记住的日子，留在这里。”，同时保留添加入口 | 原卡片内读取占位；读取失败显示“这次没能加载出来，再试一下吧。”与重试箭头，不误显示为空列表；保存中防重复，失败保留内容 |
| 备忘录 | 首页备忘录模块提供添加入口；点击从底部展开填写面板 | “今天有什么想记录的吗？”，同时保留添加入口 | 原卡片内读取占位；读取失败显示“这次没能加载出来，再试一下吧。”与重试箭头，不误显示为空列表；保存中防重复，失败保留内容 |
| 保存新条目 | 保存成功收起面板，并在首页对应模块显示新条目 | 新条目出现后不再展示该模块空态 | 失败不收起、不清空输入，不把失败显示成成功 |

底部面板新增流程已确认：有未保存内容时关闭，提示“放弃这次记录吗？”，提供“继续填写”和“放弃”；继续填写保留原输入，放弃则关闭且不新增记录，没有内容时可直接关闭。该关闭确认不等于自动保存草稿。删除纪念日或备忘录前二次确认；成功移除，失败保留原条目并提示重试。编辑入口形态和具体保存／删除失败文案尚未全部确认，不直接复制聊天回复失败文案。

既有确认不变：纪念日手动管理，支持每年和一次；备忘录可新增、查看、编辑、删除，完成后打钩、划线并下沉至未完成项下，不做定时提醒。首页保留日期、关系天数、双人头像状态与日夜切换；底部四项：首页｜聊天｜动态｜设置。

### 3.1 列表与资料表单统一反馈（本轮确认）

- 动态、共同记忆等列表和资料编辑表单沿用同一套原则：加载中占位，失败在原位置提示并提供重试。
- 保存过程中防止重复提交；失败保留用户输入，不误报保存成功。
- 首页纪念日与备忘录读取失败使用已选文案；其他入口的具体文字尚未逐一确定，不自行假定全部使用同一句。
- 首次没有内容与读取失败必须分开，不能用空态掩盖失败；聊天等待回复采用下方专用标注，不使用列表占位或底部跳动点替代。

### 3.2 聊天等待与回应出现（按发起人参考图确认）

- 位置：聊天页顶部角色头像旁、梦角名字下方的副标题区域。
- 用户消息发送成功、等待梦角回应时显示“正在输入中”。这只表示等待回应的界面状态，不证明真人正在操作。
- 收到回应后结束输入状态，消息出现在对话区；不采用此前提出的对话底部跳动三个点。
- 回复失败时同样结束输入状态，显示既定失败文案和重试箭头，不继续无限显示正在输入。
- 消息出现的具体动效、流式或整段显示尚未单独确认，不在标注中擅自锁定。
- 仅归纳参考图中指示的位置，不上传参考截图或将截图人物资料作为产品默认值。

### 4.1 空对话、动态发布与首次引导恢复（v0.3 已确认）

| 场景 | 页面入口与操作结果 | 状态与反馈 |
| --- | --- | --- |
| 首次空对话 | 首次进入聊天时，梦角依据用户已填写的既有关系自然开场 | 不采用初次相识式自我介绍，不杜撰共同经历；等待与失败采用既定聊天反馈 |
| 动态发布 | 点击动态页右上角“＋”进入独立发布页，填写文字并选择照片 | 成功返回动态列表并显示新动态；失败保留内容并允许重试。发布中防止重复提交及未保存退出确认沿用通则；专用细节待评审 |
| 动态为空 | 列表读取成功且无动态 | “把想分享的日常，留在这里。”，保留“＋”发布入口 |
| 共同记忆为空 | 列表读取成功且没有记忆 | “这里还没有共同记忆，慢慢聊，不着急。”；读取失败不得展示此空态 |
| 首次引导中途退出 | 保留已填写的未完成关系资料 | 下次登录从未完成步骤继续，不要求全部重填；恢复时仍需遵守账户隔离，实际保存能力待验证 |
| 首次引导重新填写 | 引导内提供“重新塑造”退回按钮 | 点击先确认“要重新填写这次的关系资料吗？”，确认后清空本次未完成资料、回到引导第一步；未确认不清空。该操作不用于重置已建立关系，不影响已有聊天或记忆 |

“重新塑造”是用户明确指定的按钮名称，不据此增设角色重建、关系切换或已建立关系清空功能。动态和共同记忆的空态文案均由发起人确认；不从空态推定自动记忆授权。

## 6. 检查与交接

本轮只进行文档检查与确认追溯，不进行前端开发、原型制作、动画渲染、真机或功能测试。全部状态仍需后续实现与测试取得证据。

核心结论：启动不是独立等待结束后硬切页面，而是品牌进入目标位置、目标内容同时显现；启动失败保留现场并可重试。首页新增操作统一底部面板，空态有确定文案，保存失败保留输入。

下一步建议：面板关闭、列表与表单通用反馈及聊天等待状态已补；继续对齐各页面专用空态、图片上传与动态发布等状态；PM 将本文件的新增确认合入 PRD，QA 按逐项规则复核，不因本轮部分状态补齐而宣告第二阶段整体验收。

## 7. 登录失败与返回路径（v0.4 已确认）

依据：发起人确认本轮登录反馈方案。

| 场景 | 反馈与恢复 |
| --- | --- |
| 验证码错误或过期 | 停留当前页，提示“验证码不正确或已过期”，可重新输入或重新获取 |
| 短信发送失败 | 保留手机号，提示“验证码暂时没能发出”，提供重试 |
| 登录失败 | 保留手机号和已输入验证码，不跳回启动页；失效验证码不因保留而继续有效 |
| 登录页返回 | 回到启动品牌页，不清除已输入手机号 |

登录成功仍按已确认账户资料状态进入引导或首页。返回品牌页后的重新进入操作尚待具体标注，不能自动形成品牌页与登录页反复跳转。验证码安全时限、次数及账号归属规则交 PM 与安全评审，不在此新增阈值。

本轮只补文档，未验证短信、登录或页面返回的实际行为。
