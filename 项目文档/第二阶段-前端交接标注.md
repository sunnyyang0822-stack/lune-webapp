## 1. 目标与状态

目标：为后续前端提供页面入口、操作结果、空态、加载及失败反馈的产品标注。本轮仅写已确认的交互，不编写页面代码、不选技术、不提供聊天增长优化方案。

本轮实际完成：与发起人确认启动加载与转场、启动失败、首页两个模块空态，以及新增填写面板的成功失败行为。其余页面沿用先前确认，并明确未补齐处；不将本文件视为所有前端状态已经验收。

依据：2026-10-30 本聊天中发起人的直接选择与确认。只公开产品结论，不含真实用户资料、上传素材、私人聊天或本地参考媒体路径。需求确认不是功能或动效测试。

## 2. 启动加载与页面入口（已确认）

| 标注 | 用户可见行为 |
| --- | --- |
| 打开 LUNE | 全屏使用当前日／夜模式的渐变，居中仅呈现品牌，不显示情头 |
| 品牌文字 | LUNE；固定中文主题句“爱与故事，永不落幕。”，不新增或改写品牌文案 |
| 加载指示 | 不显示虚假进度，不为展示而刻意延长等待；轻微呼吸效果仅为此前建议，尚未单独确认 |
| 加载成功 | 品牌上浮至目标页面的正确品牌位置，目标页面内容同步显现，形成连续过渡 |
| 未登录 | 以相同过渡显现手机号登录／注册页 |
| 已登录、首次资料未完成 | 以相同过渡显现首次关系引导页 |
| 已登录、资料已完成 | 以相同过渡显现首页 |
| 启动失败 | 保留品牌及渐变，显示“这次没能顺利打开，再试一下吧。”，下方仅显示重试箭头；不因失败自动跳转或清空资料 |
| 重试 | 箭头重试启动加载，成功后再按账户状态进入对应页面，不把加载失败当作未登录或没有资料 |

转场细则：首页、登录、首次引导都沿用品牌上浮与页面内容同步显现。具体速度、曲线、首页品牌落点和减少动态效果的适配尚待制作及后续评审；本文件不擅自写成已确认数值，不制作动画代码。

## 3. 首页纪念日与备忘录（本轮确认）

| 模块／操作 | 入口与结果 | 空态 | 加载与失败 |
| --- | --- | --- | --- |
| 纪念日 | 首页纪念日模块提供添加入口；点击从底部展开填写面板 | “把值得记住的日子，留在这里。”，同时保留添加入口 | 初始读取与保存中的具体视觉待确认；保存失败保留填写内容并提示重试 |
| 备忘录 | 首页备忘录模块提供添加入口；点击从底部展开填写面板 | “今天有什么想记录的吗？”，同时保留添加入口 | 初始读取与保存中的具体视觉待确认；保存失败保留填写内容并提示重试 |
| 保存新条目 | 保存成功收起面板，并在首页对应模块显示新条目 | 新条目出现后不再展示该模块空态 | 失败不收起、不清空输入，不把失败显示成成功 |

本次底部面板仅明确新增入口，不推定编辑、删除、确认取消、关闭草稿等操作已经沿用同一面板形式。保存失败的具体文案与重试图标仍待确认，不直接复制聊天回复失败文案。

既有确认不变：纪念日手动管理，支持每年和一次；备忘录可新增、查看、编辑、删除，完成后打钩、划线并下沉至未完成项下，不做定时提醒。首页保留日期、关系天数、双人头像状态与日夜切换；底部四项：首页｜聊天｜动态｜设置。

## 4. 其他已确认反馈（沿用，便于前端查阅）

| 页面／场景 | 入口／操作结果 | 已确认反馈 | 尚未明确 |
| --- | --- | --- | --- |
| 聊天／发送文字照片 | 聊天导航进入，输入文字或选择照片并发送 | 发送失败保留文字与照片并可重试 | 上传中、发送中、读取历史时的具体表现 |
| 聊天／梦角回复失败 | 用户消息已发送，梦角未成功回复 | “有句话没能抵达你这里，稍后再试试吧。”，只显示重试箭头，无“再试一次”按钮文字；只恢复该次失败回复，不重发用户消息 | 回复等待中的表现、连续重试限制 |
| 聊天／图片理解不足 | 照片已到达但无法辨认 | 自然澄清，不编造细节；不混同上传失败 | 对应样例由 AI 专家定义 |
| 设置／记忆纠错 | 设置→共同记忆→编辑→保存 | 成功显示“已更新”，后续使用新内容；失败保留修改、提示未保存并可重试 | 空记忆文案、载入及保存中状态、删除成功失败反馈 |
| 设置／主动关心 | 只有一个总开关，早晚仅设时间，不设子开关 | 定时失败不补发、不关配置，在设置提示本次未成功；不控制动态互动 | 总开关初始状态、读取和保存失败反馈等 |
| 手机通知开启提示 | 未开通知时，第一次主动关心触发提示 | “关闭”仅关本次；“之后不再提醒”仅停提示；均不关闭主动关心。告知设置→主动关心→手机通知路径，消息仍在聊天内接收 | 关闭本次后的再现时机、具体权限失败反馈 |
| 手机主动通知 | 要求未打开产品也能收到；点击进入聊天 | 通知显示梦角名字和正文，不默认隐藏 | 实际平台触达、登录失效后的跳转等需验证／确认 |

## 6. 检查与交接

本轮只进行文档检查与确认追溯，不进行前端开发、原型制作、动画渲染、真机或功能测试。全部状态仍需后续实现与测试取得证据。

核心结论：启动不是独立等待结束后硬切页面，而是品牌进入目标位置、目标内容同时显现；启动失败保留现场并可重试。首页新增操作统一底部面板，空态有确定文案，保存失败保留输入。

下一步建议：继续对齐首页面板取消和草稿行为，随后覆盖各主要页面的加载与失败状态；PM 将本文件的新增确认合入 PRD，QA 按逐项规则复核，不因本轮部分状态补齐而宣告第二阶段整体验收。
