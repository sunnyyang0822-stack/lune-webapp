# LUNE 第四阶段：数据模型设计

版本：v0.1（初稿，待发起人确认）。日期：2026-10-30。负责人：数据模型角色（按 LUNE-DEC-015 由 PM 派出的子 Agent 承担，属**角色合并**，不构成独立第三方评审）。

阶段依据：[DEC-018](项目决策记录.md) 第三阶段技术方案通过、进入第四阶段。上游基线：[PRD v1.0](02-产品设计与PRD.md)、[技术方案 v0.1](03-技术方案设计.md)。

## 1. 目标与边界

目标：把已确认的产品规则落成一致的数据结构，使"记忆删除后停止使用""动态删除后来源停用""失败不假报成功""跨账户隔离"等要求有**可实现、可核对**的载体。

边界：**本文只做数据模型**。不定义接口路径与请求／响应格式（属第五阶段 API 契约）、不写迁移脚本、不写业务代码、不选 ORM 版本。字段命名与类型为逻辑模型，物理实现可在不改变语义的前提下调整。

标记沿用：**已确认**（有 DEC／PRD 依据）／**建议（D）**／**待确认（P）**／**未验证（V）**。

## 2. 设计原则

| 原则 | 内容 | 依据 |
| --- | --- | --- |
| 账户强制隔离 | 每张业务表带 `account_id`，所有查询强制带该条件；缺失即视为缺陷 | DEC-001、安全冻结版 §3 |
| 软删除 + 状态位 | 不使用物理删除表达"用户已删除"，状态区分"在用／停用／已删除" | DEC-008、DEC-009 |
| 来源可追溯 | 记忆与内容必须能追溯到来源类别与来源标识 | DEC-008、安全冻结版 §3.5 |
| 删除分三层表达 | 界面移除、停止作为依据、物理副本清理是三种不同事实，模型中分别可查 | 安全冻结版 §5 |
| 幂等优先 | 发布、评论、消息、通知、编排均带幂等键，重复提交不产生第二条 | DEC-012 |
| 结果诚实 | 任何"成功"必须有对应记录，未知状态单独存在，不用空值冒充成功 | DEC-012、QA 冻结复核 R12 |
| 时间统一 | 全部时间以 UTC 存储；用户时区只用于展示与定时计算 | DEC-010、FR-03 |
| 隐私最小化 | 不存消息原文到日志表；手机号只存必要的可检索标识；媒体只存引用与元数据 | DEC-001、DEC-011 |

## 3. 实体总览

| 域 | 实体 | 作用 |
| --- | --- | --- |
| 账户 | `account` | 用户账户与状态、演示标记 |
| 账户 | `auth_code_request` | 验证码请求与尝试记录（含演示模式） |
| 账户 | `session` | 登录会话 |
| 关系 | `profile` | 唯一梦角与既有关系资料 |
| 关系 | `proactive_setting` | 主动关心总开关、早晚时间、时区、通知偏好 |
| 内容 | `message` | 聊天消息（用户／梦角） |
| 内容 | `post` | 动态（用户或梦角发布） |
| 内容 | `post_interaction` | 点赞与评论 |
| 内容 | `media_asset` | 照片与临时文件元数据 |
| 记忆 | `memory` | 共同记忆条目与来源、状态 |
| 记忆 | `memory_revision` | 纠错历史（支撑"已更新"） |
| 首页 | `anniversary` | 纪念日（每年／一次） |
| 首页 | `memo` | 备忘录 |
| 编排 | `agent_run` | 一次请求的编排实例 |
| 编排 | `agent_step` | 编排的每一步轨迹 |
| 通知 | `notification_job` | 待发出／已生成的主动消息 |
| 通知 | `notification_log` | 生成、投递、失败的真实结果 |
| 合规 | `consent_record` | 用途告知的确认记录 |
| 合规 | `deletion_request` | 删除／注销请求与结果（含未知态） |

关系要点：`account` 1—1 `profile`、1—1 `proactive_setting`；`profile` 1—N `message`／`post`／`memory`／`anniversary`／`memo`；`post` 1—N `post_interaction`；`agent_run` 1—N `agent_step`；`notification_job` 1—1 `notification_log`（可多条投递尝试）。

### 4.14 agent_run / agent_step

| 实体 | 字段要点 |
| --- | --- |
| `agent_run` | id, account_id, trigger(chat/post_comment/proactive/photo), status(running/succeeded/failed/partial), idempotency_key UNIQUE, started_at, ended_at |
| `agent_step` | id, run_id, step_name(context/memory_retrieve/generate/memory_extract/state_update/notify), status, attempt, error_class, duration_ms, started_at, ended_at |

**设计意图**：`agent_step` 是赛道 B"任务拆解、工具调用、状态管理、多步容错恢复"的证据载体，也是"结果未知先核实"（DEC-012）的判据来源。步骤表**不存消息原文**，只存步骤与结果元数据。

### 4.15 notification_job / notification_log

| 实体 | 字段要点 |
| --- | --- |
| `notification_job` | id, account_id, kind(morning/evening/spontaneous), scheduled_at_local, scheduled_date_local, timezone, status(scheduled/generated/sent/failed/skipped), dedupe_key UNIQUE(account_id, kind, date) |
| `notification_log` | id, job_id, channel(webpush/inapp), result(generated/shown/delivered/failed), fail_class, attempted_at |

**关键**：`dedupe_key` 保证同日同类不重复；`status = skipped` 用于"错过不补发"；`result` 分开记录"已生成／已显示／已投递"三种事实，禁止用其一替代另一（安全冻结版 EV-08）。

## 5. 删除语义矩阵（对应 DEC-008、DEC-009、DEC-013）

| 触发 | post | post_interaction | memory（source 指向它） | 旧聊天 message | media_asset |
| --- | --- | --- | --- | --- | --- |
| 用户删除自己的动态 | status→deleted | 一并 status→deleted | source 命中者 status→disabled | 保留 | 该 post 引用的照片标记待清理 |
| 用户删除单条记忆 | — | — | status→deleted（`origin=manual` 可重新记住） | 保留 | — |
| 用户删除备忘录／纪念日 | — | — | 若曾作为来源则 disabled | 保留 | — |
| 注销账户 | 全部 deleted | 全部 deleted | 全部 deleted | 全部 deleted | 全部待清理 |
| 退出登录 | 不变 | 不变 | 不变 | 不变 | 不变 |
| 视觉「删除成功」 | 仅证明 status 已落库 | 同 | 同 | — | **不证明第三方副本已清除** |

表中所有 delete 均为状态变更，物理清理由后台任务按保留策略执行，并由 `deletion_request` 记录结果；**不得以界面消失替代成功验证**。

## 6. 状态机

| 对象 | 允许流转 | 说明 |
| --- | --- | --- |
| message.status | pending → sent；pending → failed；pending → unknown → (sent/failed) | unknown 必须由核实后转为终态 |
| post_interaction.status | pending → saved；pending → failed；pending → unknown | 评论失败不阻塞动态本身 |
| memory.status | active → disabled；active → deleted；disabled → deleted | 不允许从 deleted 回到 active，除非 `origin=manual` 且用户明确要求 |
| agent_run.status | running → succeeded／failed／partial | partial 用于回复成功但记忆抽取失败（DEC-012 失败分离） |
| notification_job.status | scheduled → generated → sent；任一 → failed／skipped | skipped 表示错过不补发 |

## 7. 索引与查询支撑

| 需求 | 支撑方式 |
| --- | --- |
| 聊天气泡按时间翻页 | `message(account_id, created_at)` |
| 记忆列表与"何时用过" | `memory(account_id, status)`、`memory(last_used_at)` |
| 删除传播（来源命中） | `memory(source_type, source_id)` |
| 动态流分页 | `post(account_id, created_at)` |
| 防重复提交 | 各表 `client_idempotency_key` 唯一索引 |
| 同日同类去重 | `notification_job.dedupe_key` 唯一索引 |
| 编排轨迹回看 | `agent_step(run_id, started_at)` |
| 演示数据重置 | `account.is_demo` 过滤一键清理 |

## 8. 保留与清理

| 数据 | 策略 | 状态 |
| --- | --- | --- |
| 临时照片 | 未被引用时按清理期删除 | 建议（D），期限待技术核实 |
| 编排轨迹 | 保留最近若干天，用于答辩与排障 | 建议（D） |
| 验证码请求 | 过期后保留短期用于频控统计 | 待安全评审（SEC-01） |
| 注销残留 | 记录在 `deletion_request`，第三方副本不可承诺 | 已确认边界（DEC-016） |
| 演示账户 | 演示前重置，仅虚构内容 | 已确认（DEC-001） |

## 9. 与验收点的映射

| 验收点（PRD §7.1） | 数据支撑 |
| --- | --- |
| 记忆可查看／纠错／删除且删除后不再使用 | `memory.status`、`memory_revision.result`、检索过滤 |
| 动态删除连同互动并停止来源使用 | `post.status`、`post_interaction.status`、`memory.status=disabled` |
| 主动问候不重复、错过不补发、失败提示 | `notification_job.dedupe_key`／`skipped`、`notification_log.result` |
| 失败不假报成功、未知先核实 | `status=unknown`、`deletion_request`、`agent_run.status=partial` |
| 跨账户隔离 | 全表 `account_id` 强制条件 |
| 照片第三方告知 | `consent_record`、`media_asset.third_party_processed` |

## 10. 未验证与待确认

**未验证（V）**：以上为逻辑设计，未建库、未跑迁移、无性能数据；索引选择与数据量假设未验证。

**待确认（P）**：
1. 验证码有效期与重发间隔的具体数值（属安全评审 SEC-01，不得由数据模型自行决定）。
2. 媒体文件大小、格式与数量上限（需技术核实平台与成本）。
3. 编排轨迹与临时照片的保留天数。
4. `post.basis` 的记录粒度：只记"有无来源"还是记录具体来源引用（后者更可审计，但要防隐私外溢）。
