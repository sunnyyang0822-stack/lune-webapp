### 5. 待确认：主动行为最小可观察边界（PM 建议，对应 A04／A05）

以下内容**尚未确认，不得作为冻结验收标准**，也不代表已执行任何功能、通知或模型测试。全部为行为方向，不指定实现、模型或数值化指标。

**A04-a 自行发布动态的信息充分判据**（替代无法判定的“足够”）

同时满足两项才可自行发布：(1) 角色侧至少存在一条用户已填写或已确认的角色事实（性格、喜好、特长、世界观任一）；(2) 当轮至少存在一条可追溯的内容来源（用户此前聊天内容、用户动态、纪念日、用户设定的时间或季节背景）。用户偏好不能替代角色事实；两项缺任一项即不发布。

虚构检查点：只填了“寡言”、未填喜好特长且当天无新情境时，动态页不出现新条目；前一天聊过“在修旧收音机”时，可出现一条与收音机相关、符合寡言口吻的短动态。

**A04-b 判定为“不发”时的可观察表现**

动态列表无新条目、聊天无主动消息；不用无依据的空泛句填充动态位；不把用户偏好写成角色自述；不因“该发一条”而虚构当天经历。

**A04-c 梦角状态的有效期**（两个选项，需发起人选择）

- 选项 1（推荐，最易判定）：状态只在当轮发生可追溯互动时更新，不设自动过期；多日无互动时保持最后一次内容。
- 选项 2：状态带来源，超过 24 小时（用户时区）无新互动后回落到中性描述。

选项 1 的可观察表现：无互动当日状态文本与前一日相同，且未出现新的情境描述，即视为规则生效。两种选项都不允许状态成为“今天用户做了什么”的推定来源。

**A04-d 每条动态评论后的承接边界**

评论只使用该动态内容与已确认信息；不把动态内容推定为线下已发生事实（用户发“今天好累”不等于知道其加班细节）；同一主题可在后续聊天自然提及，但不新增未告知细节；动态删除后按 DEC-008 停止引用；点赞不设为每条必有，评论层级与延迟不冻结。

**A05-a 首次通知提示点“关闭”后的再次出现**

建议：本自然日不再出现该提示；仅在“次日或之后命中新的主动关心、且距上次提示满 24 小时”时最多再出现一次；选择“之后不再提醒”后不再自动出现，设置内入口保留。“关闭”与“不再提醒”均不关闭主动关心，也不改变系统权限。

**A05-b 通知权限被拒或开启失败**

设置→主动关心→手机通知处显示“通知没有打开，主动消息仍会留在聊天里”，并提供“去开启”入口；不重复弹系统权限框；总开关保持开启，聊天内消息照常接收。

**A05-c 关闭主动关心时的在途处理**

已送达或已显示的系统通知不撤回（不承诺技术上可撤回）；已生成未发送的定时问候不再发送；聊天内已存在的消息保留不删除；重新开启后按原时间继续，关闭期间错过的问候不补发（沿用 DEC-010）。

## 当前评审版 v0.2（2026-10-30）

### 最新确认：账户边界、动态评论与比赛优先级（DEC-013）

发起人确认以下产品范围与优先级。

| 项目 | 已确认规则 |
| --- | --- |
| 退出与注销 | 退出后停止主动通知；重新登录仍保留账户数据；注销需二次确认，并明确数据删除范围及第三方副本无法立即保证清除的边界 |
| 首次资料 | 角色名称、用户称呼、年龄／性别、关系背景、性格、说话方式为必填；关系开始日期必填，不允许未来日期；验证码失败、过期或频繁请求时保留流程并允许重试 |
| 用户动态评论 | 用户发布的每条动态都要由梦角进行评论；评论应遵循人设、上下文与隐私边界。失败、超时和重试仍遵循 DEC-012，不假报成功、不重复评论 |
| 比赛必做核心 | 角色设定、聊天、长期记忆查看与纠错、纪念日互动、基础主动问候、隐私边界 |
| 可降级范围 | 动态、照片理解、手机系统通知；降级时需说明对体验和评分的影响 |
| 后续范围 | 复杂自动行为、完整账户注销清理、更多个性化设置 |

“每条动态都评论”是产品行为要求，不等于已验证每次模型生成或通知触达成功；评论内容仍不得编造未给出的事实。退出／注销的实际数据传播、第三方副本和通知停止能力留后续技术与安全验证。

### 最新确认：必要操作失败与重复恢复（DEC-012）

发起人接受以下统一规则，适用于已有范围内的发布、评论、资料／设置保存和删除等必要操作，不新增业务入口。

| 状态／操作 | 已确认结果与恢复要求 |
| --- | --- |
| 发布、评论或保存明确失败 | 保留输入，明确反馈并提供重试；不得假报成功 |
| 删除明确失败 | 明确提示失败，不假报已删除；实际删除传播范围仍按 DEC-008／009，不以界面消失替代成功验证 |
| 超时、结果不确定 | 先核实结果，不直接当作失败并重复操作；核实前不得报成功，也不得把未知结果当成已确定失败 |
| 连续点击或重试 | 不得产生重复发布、评论或消息；已成功回复不因此新增重新生成入口 |

已确认的用户消息发送失败保留文字照片、角色回复失败仅箭头恢复该次回复、记忆纠错实际保存成功才显示“已更新”等继续有效。此处统一的是可观察结果，具体状态呈现交由 UI/UX 对齐，核实及防重复机制留技术阶段设计，不在本阶段指定 API 或实现方案。

后续验收需覆盖明确失败、超时后实际成功、迟到结果及连续重试，核对输入保留、真实状态与实际条数；这些是验证要求，不代表已执行。QA-A06 的统一产品原则已确认，逐入口状态与返回路径仍需 UI/UX 补齐、QA 复核，不自动关闭整项评审或第二阶段。

### 最新确认：信息用途与纪念日互动（DEC-011）

发起人接受信息用途方案，并明确修正纪念日用途：纪念日需要与互动相关，当天梦角应有符合人设、关系背景与该纪念日含义的情感表达。随后确认以下触达方式。

| 信息／场景 | 已确认用途与行为 |
| --- | --- |
| 头像 | 仅用于展示，不默认交给模型分析 |
| 首页备忘录 | 不默认作为 AI 互动依据；无定时提醒的既有规则不变 |
| 用户手动设置的纪念日 | 可作为相关互动依据；当天正常聊天自然体现情感，不只是首页日期展示；不据此授权读取全部首页内容，也不授权从聊天自动新建纪念日 |
| 纪念日主动表达 | 开启主动关心时融入当天早安／晚安，不额外增加一条定时消息；关闭主动关心后不另发纪念日消息。用户主动聊天中的情感表达仍保留 |

可观察检查点（后续验证）：虚构纪念日当天，在相关聊天及开启后的早晚问候中出现与人设和该日含义相符的表达，不编造共同经历；关闭主动关心时不另发纪念日消息。头像与备忘录不得仅因位于首页而自动进入模型输入；首次照片处理告知及锁屏提示实际可见。纪念日沿用已确认的用户时区与年度／一次性设置，不另建独立定时发送机制。删除、修改后按当前有效设置互动，实际传播和失败恢复待后续验证。

安全 S-03／S-04、AI P-05 中上述用途与告知决定转为待复核；第三方事实、账户生命周期和其他评审条件仍保留。此为产品决定，不是功能或安全测试通过。

### 依据、目标与范围

产品主打保持 **Love Unfolds, Never Ends.／爱与故事，永不落幕。** 希望让专属关系在日常互动中展开，让共同经历沉淀为故事，让陪伴随时间延续。记忆、个性化承接和角色一致性作为内部行为要求支持体验，不替代品牌主张；市场需求强度和迁移意愿仍未验证。

当前范围以 [UI/UX 交接 v1.1 及最新补充](第二阶段-UIUX对齐交接.md)、LUNE-DEC-005～008 为准，优先于 DEC-002 的旧窄范围：已新增手机号短信、首页管理项、照片理解和主动动态，不能再按“B 仅限问候”排除已确认需求。用户确认需求不等于证明两天全部可实现；技术可行性在第三阶段评估，不提前指定实现。

唯一用户关系为每用户一个梦角、一段既有关系；角色背景由用户填写，不做初次相识重置、不设角色切换。底部四项：首页、聊天、动态、设置。不新增公开社区、同担匹配、AI 图片生成、语音、通话或复杂商业化。私人数据不得公开；所有演示和测试示例虚构。

## 2. 产品定位与目标

产品名称：LUNE。

Love Unfolds, Never Ends.

爱与故事，永不落幕。

A Private Space for Your Stories, Memories & Emotions.

一个珍藏专属故事、情感互动与长期记忆的私人空间。

定位与品牌保持不变。比赛验证版本聚焦用户能感受到角色理解自己、承接共同经历并保持人设；固定早晚问候提供有限的日常主动陪伴。降低用户重复设定和修正负担是待验证的价值假设，不是已证明的市场结论。
