## 2. 产品定位与目标

产品名称：LUNE。

Love Unfolds, Never Ends.

爱与故事，永不落幕。

A Private Space for Your Stories, Memories & Emotions.

一个珍藏专属故事、情感互动与长期记忆的私人空间。

定位与品牌保持不变。比赛验证版本聚焦用户能感受到角色理解自己、承接共同经历并保持人设；固定早晚问候提供有限的日常主动陪伴。降低用户重复设定和修正负担是待验证的价值假设，不是已证明的市场结论。

候选用户：持续经营特定角色的私人关系、重视人设和跨次连续性的互动用户。最终用户边界仍需与本轮对齐正文核对，不补造人口画像或付费意愿。

## 5. 主要规则与流程待合并项

| 领域 | 本聊天已明确的边界 | 需要交接的具体规则 |
| --- | --- | --- |
| 首次使用 | 不自行默认公开梦设或社交 | 角色来源、资料输入、已有关系建立、完成与返回路径 |
| 日常聊天 | 回应重视人设及个性化承接 | 消息类型、发送和失败处理、跨次接续方式；是否包含照片及其限制 |
| 记忆 | 不编造共同经历，不承诺永不遗忘，实际内容不公开 | 记录什么、如何采纳、如何查看修改删除、现实与剧情冲突如何处理 |
| OOC 修复 | 合理修复，不以强改用户设定掩盖问题 | 用户如何反馈、如何恢复、修复后记忆与剧情如何承接 |
| 早晚问候 | 固定问候不等于复杂自主关心；未打开产品的预期不能被悄悄替换 | 时间和时区口径、接收意愿与暂停、重复和错过的处理、触达预期 |
| 首页及其他入口 | 四张静态图只证明相应视觉交付存在 | 纪念日与备忘录规则、动态和设置是否属于比赛范围、入口行为及异常状态 |

只有从实际对齐正文获得的规则才能改为“已确认”。PM 不在本轮代专业 Agent 决定这些答案；技术可行性在第三阶段评估，数据库与 API 留给其对应阶段。

## 6. 验收条件草案与评审责任

以下是 PM 从已确认目标提出的评审起点，尚未替代 QA 正式验收条件，也不代表已执行测试。

| 对应目标 | PM 验收草案 | 待补齐 |
| --- | --- | --- |
| US-01 | 在约定的跨次任务中，能承接已认可的重要经历，不把未发生内容当作经历 | AI 专家给出记忆范围与虚构样例，QA 明确预期和失败判据 |
| US-02 | 约定样例中角色遵循设定和已确认的人物逻辑，偏差有明确修正路径 | 人设基线、样例、修正流程和评判方式 |
| US-03 | 对已知信息作与上下文相关的承接，信息不足时不假装知道现实行为 | 允许使用的信息边界、正反例 |
| US-04 | 按确认时间及控制设置处理问候，角色表达一致，说明实际触达限制 | 用户控制、重复和失败规则、技术阶段可行性验证 |
| US-05 | 公开交付和演示仅有虚构或充分脱敏内容，产品数据控制符合已确认规则 | 安全评审、产品内控制流程和后续验证方式 |

UI/UX 提交流程及视觉确认，AI 专家补行为规则，QA 补可执行验收条件，安全角色补隐私评审。PM 整合冲突和范围，发起人确认基线。尚未发现的交付不能勾选完成。
