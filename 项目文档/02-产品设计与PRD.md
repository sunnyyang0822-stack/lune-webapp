### 最新确认：动态删除的使用范围（DEC-008）

发起人已明确接受以下方案，替代本文及其他评审输入中“动态删除后的使用范围待定”的旧状态：

| 对象 | 确认结果 |
| --- | --- |
| 被删除动态及其点赞、评论 | 删除，不再展示 |
| 该动态及其照片作为信息来源 | 停止用于后续聊天、动态、评论、状态或问候；不能因旧聊天仍可见而恢复该删除来源的使用 |
| 仅由被删除来源形成的共同记忆 | 同步停用，不再驱动后续互动；不以“列表仍有／没有”代替停止使用验证 |
| 其他独立来源明确确认过的同一事实 | 可保留和使用；若用户另删对应记忆，仍遵循记忆删除后不再使用的规则 |
| 旧聊天原文 | 保留，不自动抹除；展示历史不等于重新授权使用被删来源 |
| 原图及第三方副本实际清理 | 技术阶段核实可实现范围并如实告知，不承诺立即清空全部副本 |

虚构验收输入：一条“旧收音机”动态是角色某项经历的唯一来源，删除后不得再据它提及该经历；另一条“喜欢修收音机”的事实曾由用户在独立资料中明确确认，则可保留，但不能藉此继续引用已删照片或动态细节。旧聊天中既有原文可回看，不能据此恢复单一删除来源的后续使用。

此为产品决定，不是删除传播或物理清理能力验证；QA-A02／S-01／AI P-01 的决定部分已明确，QA 与安全据本规则复核，具体技术保证及失败处理仍按阶段推进。

### 依据、目标与范围

产品主打保持 **Love Unfolds, Never Ends.／爱与故事，永不落幕。** 希望让专属关系在日常互动中展开，让共同经历沉淀为故事，让陪伴随时间延续。记忆、个性化承接和角色一致性作为内部行为要求支持体验，不替代品牌主张；市场需求强度和迁移意愿仍未验证。

当前范围以 [UI/UX 交接 v1.1 及最新补充](第二阶段-UIUX对齐交接.md)、LUNE-DEC-005～008 为准，优先于 DEC-002 的旧窄范围：已新增手机号短信、首页管理项、照片理解和主动动态，不能再按“B 仅限问候”排除已确认需求。用户确认需求不等于证明两天全部可实现；技术可行性在第三阶段评估，不提前指定实现。

唯一用户关系为每用户一个梦角、一段既有关系；角色背景由用户填写，不做初次相识重置、不设角色切换。底部四项：首页、聊天、动态、设置。不新增公开社区、同担匹配、AI 图片生成、语音、通话或复杂商业化。私人数据不得公开；所有演示和测试示例虚构。

### 核心流程与确认规则

| 编号 | 流程 | 已确认产品规则 |
| --- | --- | --- |
| FR-01 | 手机登录 → 新号码自动注册／已有号码登录 → 资料检查 → 首页 | 仅手机号短信验证码，不增加其他登录方式；验证码详细规则和安全评审待补 |
| FR-02 | 首次分步填写 → 核对／修改 → 确认 | 角色称呼、对用户称呼、角色年龄性别、关系背景、性格及说话风格必填；口头禅、喜好特长、世界观及双方头像可跳过。不额外将说话示例设为必填。资料字段与原文逐项一致，日期输入边界见待决项 |
| FR-03 | 首页 → 纪念日／备忘录管理 → 保存返回 | 展示双方头像及各自状态、日期和关系天数；无头像使用对应名字首字；开始日计第 1 天；日夜切换放首页。纪念日手动管理、每年或一次；备忘录可增查改删，完成后勾选、划线并置于未完成项下，无定时提醒。取消完成和同组排序待定 |
| FR-04 | 聊天 → 文字／照片发送 → 角色文字回应 | 唯一梦角；理解图片，不能仅凭配文泛答，不确定时澄清；发送失败保留输入及照片并提供重试。不提供单条复制、删除或重生成。聊天增长后的体验待技术阶段评估 |
| FR-05 | 私人动态 → 发布／点赞／评论 → 可回聊天承接 | 用户可发文字及照片；梦角只发文字，可无用户即时操作而自行发动态。频率符合人设，不统一每日条数。喜好特长未填且相关信息不足时，角色暂不发动态；角色信息和用户偏好不能混用。用户删除自己的动态时连同点赞评论移除 |
| FR-06 | 设置 → 修改角色关系资料 → 保存 → 延续原关系 | 保留聊天、动态和共同记忆，后续使用新设定；新旧冲突处理待行为定义 |
| FR-07 | 设置 → 共同记忆 → 查看／纠错／逐条删除 | 纠错成功显示“已更新”，后续用新内容；保存失败保留修改、提示未保存并可重试。删除后不得继续作为后续互动依据，旧聊天保留；不能因旧聊天而自动恢复已删除条目。实际行为与技术保证需衔接 |
| FR-08 | 设置 → 主动关心 → 总开关及早晚时间／手机通知 | 最新决定替代拒绝统一开关的旧答复：总控定时早晚及符合人设的偶尔主动聊天，不控制动态发布、点赞评论。定时失败不补发、保留开关并提示。要求未打开产品也收到手机系统通知，显示梦角名及正文，点击回聊天；实际触达仍待验证。首次未开启通知的主动关心触发提示，“关闭”仅关本次，“之后不再提醒”仅停止提示，不关闭功能；告知设置→主动关心→手机通知路径。只保留总开关，早晚仅设时间，无子开关；初始状态、重复、时区等见 v1.1 未决项 |

关系日期由用户填写；未在交接中确定是否必填、未来日期或特殊日期边界，不自行增加规则。用户自己的名称、头像首字对应字段等资料结构仍需统一。

## 2. 产品定位与目标

产品名称：LUNE。

Love Unfolds, Never Ends.

爱与故事，永不落幕。

A Private Space for Your Stories, Memories & Emotions.

一个珍藏专属故事、情感互动与长期记忆的私人空间。

定位与品牌保持不变。比赛验证版本聚焦用户能感受到角色理解自己、承接共同经历并保持人设；固定早晚问候提供有限的日常主动陪伴。降低用户重复设定和修正负担是待验证的价值假设，不是已证明的市场结论。

候选用户：持续经营特定角色的私人关系、重视人设和跨次连续性的互动用户。最终用户边界仍需与本轮对齐正文核对，不补造人口画像或付费意愿。
