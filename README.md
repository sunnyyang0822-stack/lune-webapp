## 项目背景、定位与价值

LUNE 希望提供一个可以安放情感、珍藏回忆、延续专属故事的私人空间。产品探索关注情感互动、专属关系持续性、私人故事积累、珍贵互动的保存与用户对私人世界的掌控。

目标用户探索优先关注梦向互动用户、有稳定梦设和特定梦角的用户、对角色长期投入情感的用户，以及重视私人故事与互动记忆的用户；也可以研究同人创作者和具有相似需求的人群。这些是探索方向，不能代替真实需求验证。

## 项目原则

- 先找到具体人群的真实痛点，再考虑扩展；必须说明用户为什么愿意专门使用 LUNE，而不是直接使用通用 AI。
- 尊重私人设定和用户控制权；不默认公开社区、同担匹配或 AI 图片生成。
- 区分已有证据、初步假设和尚待验证内容，不编造需求或调研结果。
- 控制两天开发范围，每阶段形成交付物，经发起人明确确认后再进入下一阶段。
- 项目文档、Issue、代码注释和开发记录原则上使用简体中文。

## 后续研发流程

需求分析 → 产品设计 / 用户故事 / PRD → 技术方案设计 → 数据模型设计 → API 契约设计 → 前后端任务拆分 → 开发实现 → 单元测试 → 接口测试 / 契约测试 → 联调 → E2E 测试 / 回归测试 → 预发环境验证 → 上线 → 监控 / 日志 / 迭代。

完整保留各环节，逐阶段验收；当前不提前开展后续阶段。

## 开发交接（给接手实现的 Agent）

本仓库是 LUNE 的唯一事实来源，接手开发时**只需读仓库，不需要任何聊天上下文**（DEC-020）。

**必读顺序**：`AGENTS.md` → 本 README → [PRD v1.0](项目文档/02-产品设计与PRD.md)（唯一研发基线）→ [技术方案](项目文档/03-技术方案设计.md) → [数据模型](项目文档/04-数据模型设计.md) → [决策记录](项目文档/项目决策记录.md)（DEC-001～020）。

**禁区**：

1. 不得修改已确认需求；发现不可行须回报并走范围变更，不得静默降级。
2. 不得提交密钥、真实用户内容、真实梦设或真实聊天记录；示例全部虚构。
3. 失败语义按 DEC-012 实现：明确失败保留输入可重试、未知结果先核实、连点不重复。
4. 通知与号码归属必须如实标注：iOS 未取证、本版不提供换号与回收号保护（DEC-016）。
5. 不得把"云原生"表述为满配（DEC-019 为部分满足）。
6. 不得声称已验证任何 V 类能力（通知真实送达、删除传播、第三方副本、跨账户隔离、模型效果）。

**交付物**：可运行 Demo；README 部署步骤；`Dockerfile` 与 `docker-compose`（web／worker／db）；`agent_step` 轨迹截图；3 分钟录屏；架构图（赛道 B 必交）。
